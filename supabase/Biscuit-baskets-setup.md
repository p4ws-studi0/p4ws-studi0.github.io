# Biscuit baskets

`/biscuit-baskets` is a separate page reached through the Paws HQ menu. It reuses Paws HQ typography, themes, and sign-in. The alphabetical directory has search, town/status filters, and Clear filters. Open a location for a dedicated visit history, or choose Log visit to open a labeled form. Visits keep the same five fields: literal date, items given, person spoken to, town at visit, and notes. Staff explicitly choose Save visit or Cancel; moving between fields never writes data. New forms default to today's date and the location's town. Opening an untouched form does not mark changes as unsaved or create a database row. Failed or ambiguous writes keep their existing retry, revision-conflict, and same-ID reconciliation protections.

The history presents readable rows with Edit/Delete controls and expandable long notes. The directory becomes stacked rows on small screens, keeping Log visit visible without a horizontal scroller. The location form requires a name and optionally accepts town, status, and status notes. All locations returns to the filtered directory. The directory's Latest entry label follows the retained record order; it does not infer missing years or imply that an unknown-year date is chronologically newer.

Location statuses are **Active**, **Closed**, and **Not returning**. These flags are separate from deletion. The original closed/do-not-return markers are retained in status notes and the complete source rows. Dates without a year remain unknown, as requested; explicit years remain as entered. Histories containing unknown imported dates retain the recorded source-group order, newest groups first. New visits appear above that history and sort by known full dates, then newest insertion order. Histories with complete dates sort by date. Sorting never changes stored date text or invents missing years. Repeated visit dates remain separate entries.

Deleting a visit is reversible from Deleted visits or the five-second Undo notice. Deleting a location preserves all of its visits, including individually deleted entries. Restoring the location brings its history back. The server blocks creating or updating visits for a deleted location until it is restored.

## Storage and access

Run `biscuit-baskets-setup.sql` in the existing Supabase project after Tours membership setup. It safely creates three tables: `hq_biscuit_locations`, `hq_biscuit_visits`, and `hq_biscuit_sources`. Access uses the existing active Paws HQ workspace membership, including guest accounts. The two working tables allow authenticated insert/update; the archive is read-only. This page adds no access tier or account enrollment, and permanent deletion is not granted.

The server controls audit stamps, actor IDs, revisions, and deletion timestamps. Browser updates filter by the last loaded revision. IDs, creation details, source order, source metadata, original year context, and each visit's parent location are immutable. Browser-created records cannot claim imported metadata. Changing a visit locks its undeleted parent against simultaneous deletion for that transaction.

Location text limits are 500 characters for name, 200 for town, and 20,000 for status notes. Visit text limits are 120 for date, 20,000 for items given, 500 for person spoken to, 200 for town, and 20,000 for notes. Original source rows retain all 39 cells; visit metadata retains its original column number and full raw group span. The complete source archive retains headers, blank rows, flyer labels, and the unassigned final marker. The CSV supplies no flyer target URL.

Import privately with stable UUIDs. Filter out existing IDs before inserting and retain `ON CONFLICT DO NOTHING` as a final duplicate guard. PostgreSQL runs a before-insert trigger even for a conflicting ID, so skipping existing visits before the trigger allows repeated imports when their location has since been deleted. Preserve working values and original metadata exactly. A repeated import must not duplicate entries, revive deleted records, or overwrite later edits. The source has 24 named locations, 61 visits, and a 29-row, 39-column full archive. All imported visit `source_year` values remain null. Do not commit source records, import scripts, credentials, or fixture databases to the public website repository.

## Validation

Run `node --test tests/*.test.cjs` for application checks. Run `biscuit-baskets-rls-check.sql` after setup for approved account operations, partial/literal values, field limits, audit and revision rules, immutable source/parent/year metadata, reversible location and visit deletion, deleted-parent protection, read-only archive access, and anonymous/nonstaff/inactive isolation. Its synthetic fixtures and membership changes roll back. If the SQL editor stops after an error, run `rollback;` before another query.

PostgreSQL-compatible checks verified every location, visit, original group span, status marker, unknown year, and the complete source archive against the private seed. Repeating setup/import preserves edits, deleted visits, deleted locations, and restoration without reviving individually deleted visits. The live rollback-only access checks and private import also passed. CSV record values remain in the protected database, never in public page assets.
