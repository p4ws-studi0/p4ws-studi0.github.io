# Potential Training Clients

`/potential-training-clients.html` is a separate page linked from the sidebar. It reuses Paws HQ typography, themes, and sign-in. The eight working fields follow the source order: owner, dog, phone, initial employee conversation, first contact, follow-up, evaluation, and outcome. Every field remains literal text, including informal dates, appointment notes, uncertain names or initials, phone formats, surrounding whitespace, and blank cells. Partial records are allowed; changes save when leaving a cell. Entirely blank new rows stay local until filled or removed.

Each nonblank source row is a separate client entry. The page does not infer dates, appointment times, a missing year, contact status, or outcome from freeform values. A phone number embedded in an owner name stays in that field; blank Phone cells remain blank. Newest entries appear first using immutable insertion order, independent of edits and freeform date fields. Deletion is reversible from Deleted entries or the five-second Undo notice. Working edits leave original source cells unchanged.

## Storage and access

Run `potential-training-clients-setup.sql` in the existing Supabase project after Tours membership setup. It is safe to rerun and creates `public.hq_potential_training_clients` with row-level security. Only active members of the existing administrator-managed `hq_tour_staff` allowlist can select, insert, or update records, including already approved guest accounts. No accounts are enrolled and permanent deletion is not granted.

The server controls audit timestamps, actor IDs, revisions, and deletion timestamps. Updates filter by the last loaded revision. IDs, creation details, insertion/source order, and original source metadata are immutable. Browser-created rows cannot claim imported metadata. Limits are 500 characters each for owner and dog, 200 for phone, 2,000 each for initial conversation and first contact, and 20,000 each for follow-up, evaluation, and outcome. Any single nonblank field is sufficient for a partial record.

Import the CSV privately with stable UUIDv5 IDs. Filter out existing IDs before inserting and retain `ON CONFLICT DO NOTHING` as a final duplicate guard. Preserve all eight cells exactly in `source_values`, along with the source filename and actual CSV row number (at least 3). Insert in source-row order so descending insertion order places the last original entry first. Reimports must not duplicate entries, revive deleted records, or overwrite later edits. The source has its title on row 1, column headers on row 2, 23 records on rows 3–6 and 8–26, and an empty spacer on row 7. Archive the complete title, headers, and spacer privately; the spacer is not a client entry. Do not commit source records, private import scripts, credentials, or fixture databases to the public website repository.
