# Gift cards

`/gift-cards.html` is a separate page linked from the sidebar. Its compact editable table reuses Paws HQ typography, themes, and sign-in. The eight working fields are certificate number, amount, purchase date, purchaser name, purchase initials, redemption date, redeemer name, and redemption initials. Certificate numbers are read-only. The seven detail cells accept literal text, including leading zeros, amounts with currency symbols, multiline names, informal dates, and partial entries. A certificate-number-only row is a valid record. Changes save when leaving a cell. Add card opens a dropdown of existing empty certificate numbers and focuses that row for entry. It never creates a row or number; empty options are deduplicated and numbers with an active filled entry are excluded. The selected slot is rechecked before entry. All cards is the default view.

This page logs gift-card records only. It does not charge customers, issue certificates, redeem funds, or perform another financial transaction. Follow the existing checkout procedure when completing a purchase or redemption, then update the log. No balance or status is inferred from the entered values.

Deleting an entry is reversible from Deleted entries or the five-second Undo notice. Editing working fields leaves the original source cells unchanged. Missing date years remain unknown; sorting never rewrites entered dates or assigns an inferred year. The table descends by certificate number starting at the most recently purchased card with a valid full purchase date; higher numbers follow at the bottom. When no full date is present, all numbers simply descend. Same-date ties use the highest number. Previous duplicate/history rows are retained, but only one active filled record can use a certificate number. Older blank duplicates remain empty inventory slots; the Add picker offers each number once.

## Storage and access

Run `gift-cards-setup.sql` in the existing Supabase project after Tours membership setup. It is safe to rerun and creates `public.hq_gift_cards` with row-level security. Only active members of the existing administrator-managed `hq_tour_staff` allowlist can select or update existing records, including already approved guest accounts. Browser INSERT/upsert and sequence privileges are revoked, and the trigger independently rejects authenticated INSERT. No accounts are enrolled and permanent deletion is not granted.

The server controls audit timestamps, actor IDs, revisions, and deletion timestamps. Updates filter by the last loaded revision. IDs, certificate numbers, creation details, source order, and source metadata are immutable. A partial unique index prevents competing blank slots from both becoming filled and prevents restoring a filled duplicate while that number is in use. A first-use conflict never merges two customers into one blank slot. Field limits are 20,000 characters for purchaser and redeemer names and 120 for every other working field.

Import the CSV privately with stable UUIDs. Filter out existing IDs before inserting and retain `ON CONFLICT DO NOTHING` as a final duplicate guard. Preserve all eight cells exactly in `source_values`, along with the source filename and actual CSV row number (at least 3). A repeated import must not duplicate entries, revive deleted records, or overwrite later edits. The source contains 262 records, including 224 certificate-number-only entries. Do not commit source records, private import scripts, credentials, or fixture databases to the public website repository.
